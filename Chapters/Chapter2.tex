\section{Functional Requirements \applicability{Development, Hybrid, Game; Research Software Prototype}}
\begin{guidance}
Specify observable system behaviour. Give each requirement a stable identifier
and write one testable statement using ``The system shall ...''. Do not describe
implementation details unless they are genuine constraints. Detailed acceptance
criteria and test cases belong in the software testing document. Follow a
consistent requirements-engineering convention such as ISO/IEC/IEEE 29148
where applicable~\citep{ieee29148}.
\end{guidance}

\section{Non-Functional Requirements \applicability{Development, Hybrid, Game; Research Software Prototype}}
\begin{guidance}
State measurable quality requirements and operational constraints. Replace vague
terms such as \emph{fast}, \emph{secure}, and \emph{user-friendly} with measurable
targets under stated conditions. Include only attributes relevant to the project.
\end{guidance}
